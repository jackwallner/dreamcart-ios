## Held for Jack

1. The app has no translated "App Store isn't reachable" line, so RevenueCat's network and offline errors still show in English (Rollout A step 5 applies only when the line exists). Recommend adding one key and mapping RevenueCat codes 10 and 35 to it; it gets every non-English shopper a readable error.
2. Purchase failures are not logged today (only starts and completions), so no `pending` event was added (Rollout A step 6). Recommend a `purchase_pending` event if you want Ask to Buy volume; it needs a row in `docs/analytics-privacy.md`.
3. An Ask to Buy approved later unlocks on the next foreground, not while the app stays on screen: membership is the server's `is_plus`, set by the RevenueCat webhook, and there is no RevenueCat delegate. Changing that touches how membership is judged, so it is held.
4. RevenueCat dashboard: the reader only sees metadata on the current offering. DreamCart buys products by id and may have no current offering configured; until one exists every customer reads the control. To run the test, set `trial_cta` on the offering (or the Experiment arms) and keep `rating_prompt` the same on every offering.
5. Shoppers whose reminder toggle an earlier build already cleared cannot be told apart from a deliberate Off, so they stay Off until they turn it on.
6. Audit item C2 (the coin shop's stale-spinner guard can say "You weren't charged" for a purchase that settles late) is a code path only; no coins are lost. Not fixed.
